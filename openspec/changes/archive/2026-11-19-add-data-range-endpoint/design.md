# Design

## Context

Агрегат нужен одному потребителю (wallet-mcp), но по смыслу это справочный факт о
леджере, как `/currencies` и `/accounts`: без периода и без `eq_currency`.

## Decisions

**Один запрос `SELECT min(date), max(date), count(*)`** по живым операциям леджера
(`deleted_at IS NULL`) — тот же признак «живая», что у `list_user_stats`. Дата
возвращается датой `ГГГГ-ММ-ДД`: время операции потребителю не нужно, а период в
отчётах и так задаётся датами. Индексы по `(ledger_id, date)` уже есть для списка
операций, отдельный не нужен.

**Пролог — `auth_and_ledger`**, как у `/accounts`: 401 без токена, `as_user_id` для
админа и поддержки работает так же. Нет леджера — 200 с `null`/`0`, тот же контракт
«пусто, а не ошибка».

**Правок в wallet-api, wallet-gateway и схеме БД нет.** Путь под `/api/reports/*`,
читаем уже доступную роли `wallet_reader` таблицу `operation`.

## Risks / Trade-offs

- [Большой леджер: count(*) по всем операциям] → один проход по индексу леджера, порядок миллисекунд на 3000 операциях стенда нагрузочного теста; кеш не нужен.
