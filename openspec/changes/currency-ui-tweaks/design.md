# Design

## Context

`list_currencies` строит ответ через `row_to_json(fields, kColumns)`: все
значения строк из драйвера приходят текстом (`t`/`f` для boolean). Запросов
два: без леджера (только общие) и с леджером (`DISTINCT ON (iso_code)`, своя
строка вместо общей).

## Goals / Non-Goals

**Goals:** отдать флаг и принадлежность валюты, не меняя состав списка.

**Non-Goals:** фильтрация `show_in_equivalent=true` на сервере;
проверка, что `eq_currency` отчётов входит в разрешённые для эквивалента.
Отчёт в «скрытой» валюте по-прежнему считается: флаг относится к выбору в
интерфейсе, а не к допустимости запроса.

## Decisions

- **Поля, а не фильтр.** Веб берёт один справочник и для пикера
  эквивалента, и для пикеров пар, и для списка валют. Фильтр на сервере
  потребовал бы второго запроса или параметра.
  Альтернатива `?for=equivalent` отвергнута: лишний режим ради одной
  строки клиентского фильтра.
- **`is_own` вычисляется как `c.ledger_id IS NOT NULL`** в обоих запросах.
  В запросе без леджера это всегда `false`.
- **`icon_uuid` и `precision` нужны форме правки на вебе.** Без них
  форма не показала бы текущие иконку и точность валюты. Тот же состав
  строки возвращает REST wallet-api на `POST`/`PATCH` (`wallet-api:
  currency-ui-tweaks`, design D4), и веб подставляет ответ в справочник без
  перезапроса.
- **Типы в JSON.** `t`/`f` из драйвера преобразуются в JSON-boolean, а
  `precision` — в число (`row_to_json` сейчас отдаёт строки). Это либо
  отдельная обработка этих колонок, либо списки булевых и числовых колонок
  у `row_to_json`, по образцу того, как в файле уже решаются числовые поля.

## Правки в других сервисах

- **wallet-api** (`wallet-api: currency-ui-tweaks`): миграция 000026,
  колонка `currency.show_in_equivalent`. Без неё запрос этого сервиса падает,
  поэтому порядок выкатки — wallet-api, потом wallet-report. GRANT не нужен
  (`wallet_reader` читает таблицы целиком).
- **wallet-gateway**: без правок.

## Risks / Trade-offs

- [wallet-report выкачен раньше миграции → `500` на `/currencies`, веб
  остаётся со значением по умолчанию] → порядок выкатки в tasks, и веб
  молча переживает ошибку справочника (действующее требование
  `reports-shell`).
