# Design

## Context

Мотивация — proposal.md; продуктовые решения — в issue
`.github-private#10`. Схема и SQL-функции — парный change `wallet-api`
(`debts`, его design D5–D7); здесь только вызов, `LEFT JOIN` и форма
ответов.

Что есть сейчас:

- wallet-report читает базу ролью `wallet_reader` и вызывает функции
  wallet-api. Балансовые итоги `total_eq`/`capital_eq`/`net_worth_eq`
  считает сам по колонкам `asset_type`, `include_in_net_worth` (набор
  `capital-assets`).
- `/wallet-turnover` и `/accounts` признак актива берут собственным `LEFT JOIN
  account_asset`; тот же приём — для `account_debt`.
- Тестовая копия синка `src/sync_repo.cpp` засевает данные интеграционных
  тестов; её порядок обязан совпадать с `kApplyOrder` wallet-api.

## Goals / Non-Goals

**Goals:**
- Долги видны отдельно и не искажают ликвидный итог.
- Один отчёт `/debts` с группировкой по контрагенту, по валютам и итогом в
  эквиваленте.

**Non-Goals:**
- Запись долгов, проценты, график платежей.
- Менять смысл существующих полей (кроме `total_eq`/`incomplete`).

## Decisions

### D1. Ликвидный итог — без активов и без долгов

`total_eq` и `incomplete` считаются по кошелькам с `asset_type IS NULL AND
counterparty_uuid IS NULL`. Это расширение уже принятой логики капитала
(`capital-assets`), по тому же признаку «не входит в ликвидные».

### D2. Новые итоги долгов

В `/balance`, каждом блоке `/balance-at-dates` и каждом бакете
`/balance-series`:

| Поле | Смысл |
| --- | --- |
| `receivable_eq` | сумма положительных остатков долговых кошельков в эквиваленте |
| `payable_eq` | сумма модулей отрицательных остатков |
| `debts_incomplete` | у части долговых кошельков нет курса |
| `with_debts_eq` | `total_eq + receivable_eq − payable_eq` |

Положительные и отрицательные остатки суммируются **по кошелькам**, а не
по контрагентам: кошелёк «Вася · USD» +100 и «Вася · EUR» −30 — это и
«мне должны», и «я должен», а не нетто по Васе. `/debts` дополнительно
показывает нетто по контрагенту.

*Альтернатива:* `net_worth_eq` включает долги. Отклонено в этом change (см.
Open Questions): меняло бы смысл существующего поля.

### D3. `/debts` строится поверх `f_debts_for_period`

Запрос функции wallet-api за период; группировка по `counterparty_uuid`
делается в wallet-report. Итог по контрагенту — сумма эквивалентов его
кошельков (`balance_to_eq`), `incomplete` — если у какого-то кошелька нет
курса. Контрагенты сортируются по модулю итога (без курса — в конце).
Нулевые и архивные кошельки отдаются, фильтрует клиент.

### D4. `kind = "debt"`

Проходит из `f_operations_for_period` без вычислений на стороне
wallet-report; в строку добавляется `counterparty_uuid` — контрагент
долговой стороны (`LEFT JOIN account_debt` по `from_uuid`/`to_uuid`), у
остальных видов `null`. Параметр фильтра `kind` принимает `debt` — так же,
как уже принимает `revaluation` (исходная посылка «`revaluation` в фильтре
нет» не совпала с кодом; решение владельца 2026-11-12). Без этого долговые
переводы нельзя отобрать на сервере: `kind=transfer` их больше не находит
(wallet-api `000036`).

### D5. `/counterparties`

Простая выборка по `counterparty` с иконкой; нужна боту для подсказок и
вебу. Права — `SELECT` на `counterparty` у `wallet_reader` (выдаёт миграция
wallet-api).

### D6. Нужны ли правки в других сервисах

- **wallet-api:** миграция, функции и роль — парный change; порядок выката:
  сначала он.
- **wallet-gateway:** путей новых нет — всё под `/api/reports/*`.
- **wallet-telegram, android-wallet:** парные changes.

## Совместимость

| Потребитель | Что видит |
| --- | --- |
| wallet-web / клиент без поддержки | новые поля игнорирует; `total_eq` теперь без долговых кошельков — ликвидный итог уменьшается на сумму выданных долгов (это и есть смысл change) |
| wallet-telegram | `counterparty_uuid` в `/accounts`, пока бот не отфильтрует, долговые кошельки остаются в выборе трат |

## Risks / Trade-offs

- [`total_eq` меняет значение у леджеров, где долги уже вели обычными
  кошельками] → смысл изменения; помечено BREAKING по смыслу, как в
  `capital-assets`. Пользователь, у которого есть кошелёк «Вася» без
  `account_debt`, ничего не заметит.
- [Забыли исключить долговые кошельки где-то в ликвидных итогах] → общий
  предикат D1 в одном месте, интеграционные тесты на каждый из трёх
  балансовых отчётов.
- [Курс на `p_to`, а не по датам проводок] → тождество `начало + поступления
  − выбытия = конец` сохраняется и в эквиваленте (как в `capital-report`).

## Migration Plan

1. wallet-api с миграцией — на test и prod.
2. wallet-report с этим change.
3. android-wallet и wallet-telegram.
4. Откат: предыдущим тегом.

## Open Questions

- Должен ли `net_worth_eq` включать долги (ликвидные + активы +
  «мне должны» − «я должен»)? Сейчас нет: итог с долгами — отдельное поле
  `with_debts_eq`, чтобы не менять смысл существующего.
