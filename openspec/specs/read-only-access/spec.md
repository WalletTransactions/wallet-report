# read-only-access Specification

## Purpose
Гарантия, что сервис физически не может изменить данные: он читает общую с
wallet-api базу единственной read-only ролью и ничего не создаёт и не мигрирует.

## Requirements

### Requirement: Единственная read-only роль подключения
Сервис SHALL подключаться к базе только по `REPORTS_DATABASE_URL` ролью
`wallet_reader`, у которой нет прав INSERT/UPDATE/DELETE и DDL. Второго
соединения с правами на запись в процессе MUST NOT быть.

#### Scenario: Попытка записи из отчётного кода
- **WHEN** отчётный код по ошибке выполняет INSERT/UPDATE/DELETE
- **THEN** Postgres отклоняет запрос на уровне прав роли, данные не меняются

#### Scenario: Не задана строка подключения
- **WHEN** сервис запускается без `REPORTS_DATABASE_URL`
- **THEN** процесс завершается с ошибкой при старте, не начиная слушать порт

### Requirement: Без провизионирования и миграций
Сервис MUST NOT создавать леджер, пользователя или любые другие сущности и
MUST NOT применять миграции. Схема и миграции принадлежат wallet-api.

#### Scenario: Пользователь без леджера
- **WHEN** аутентифицированный пользователь, ни разу не синкавший данные, вызывает отчёт
- **THEN** сервис отвечает 200 с пустым результатом и не создаёт леджер

### Requirement: Пул соединений
Сервис SHALL держать пул read-only соединений размером `REPORTS_DB_POOL_SIZE`
(по умолчанию 8), чтобы медленный отчёт не блокировал остальные запросы.

#### Scenario: Некорректный размер пула
- **WHEN** `REPORTS_DB_POOL_SIZE` меньше 1
- **THEN** процесс завершается с ошибкой при старте

#### Scenario: База недоступна при старте
- **WHEN** пул не может открыть соединения с базой
- **THEN** процесс логирует ошибку и завершается с ненулевым кодом

### Requirement: Код write-стороны не входит в исполняемый файл
Код протокола синка (`sync_repo`, `provisioning`) SHALL использоваться только
интеграционными тестами для засева данных и MUST NOT собираться в `wallet_report`.

#### Scenario: Сборка сервиса
- **WHEN** собирается цель `wallet_report`
- **THEN** `sync_repo.cpp` и `provisioning.cpp` в неё не входят
