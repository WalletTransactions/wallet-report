# ledger-resolution Specification

## Purpose
Общий пролог отчётов: от проверенного пользователя к его леджеру и к валюте
эквивалента, в которой считаются суммы `*_eq`.

## Requirements

### Requirement: Резолв леджера по пользователю
Отчёт SHALL резолвить леджер по `sub` проверенного токена (или по
`as_user_id`, см. admin-tools) через существующие `app_user`/`ledger_member`.
`device_id` не требуется.

#### Scenario: Леджер найден
- **WHEN** у пользователя есть леджер
- **THEN** отчёт строится только по данным этого леджера

#### Scenario: Леджера нет
- **WHEN** у пользователя нет ни одного леджера
- **THEN** отчёт отвечает 200 с пустым результатом (пустые списки, нулевые итоги), а не 404/500

### Requirement: Обязательная валюта эквивалента
Все отчёты с суммами SHALL требовать параметр `eq_currency` (ISO-код).
Код резолвится с приоритетом собственной валюты леджера над общей
(`ledger_id IS NULL`) с тем же ISO-кодом.

#### Scenario: eq_currency не передан
- **WHEN** параметр `eq_currency` отсутствует или пуст
- **THEN** 400

#### Scenario: Неизвестный ISO-код
- **WHEN** у пользователя есть леджер, а ISO-код не найден ни среди своих, ни среди общих валют
- **THEN** 400 с текстом «неизвестный ISO-код валюты эквивалента»

#### Scenario: Ответ содержит uuid эквивалента
- **WHEN** отчёт с суммами возвращает строки
- **THEN** в ответе есть `eq_currency_uuid`, чтобы клиент отличал «уже в валюте эквивалента» от «пересчитано по курсу»

### Requirement: Неполный пересчёт
Если для части строк не найден курс в `eq_currency`, ответ SHALL содержать
`incomplete: true`; итог `total_eq` в этом случае занижен. Итоги считаются по
всему результату в одном запросе к БД.

#### Scenario: Нет курса для одного кошелька
- **WHEN** у одного из кошельков нет курса к валюте эквивалента
- **THEN** `incomplete: true`, итог включает только пересчитанные суммы

### Requirement: Формат денег и ошибок
Денежные суммы SHALL отдаваться JSON-строками (numeric без двоичной
погрешности). Ошибки SHALL отдаваться как `{"error": "<текст>"}`;
необработанное исключение — 500 `{"error":"internal server error"}` с записью в лог.

#### Scenario: Необработанное исключение
- **WHEN** хендлер бросает исключение
- **THEN** клиент получает 500 с JSON-ошибкой без деталей, детали пишутся в лог
